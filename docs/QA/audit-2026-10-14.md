## A. Reliability — failure paths & honest degradation

**A-1 [major] `/api/history` has no KV-failure handling → raw 500.**
`apps/api/src/index.ts:351` awaits `readHistory` with no try/catch;
`history.ts:119-121` does a bare `kv.get`. A KV read failure (binding
outage) surfaces as `500 internal_error` via `app.onError` instead of
degrading honestly. The route AND module also have **zero tests** (see
C-1). *Fix:* wrap in try/catch → serve the empty-history shape (sparklines
fall back to the local window, every displayed point still real) or a calm
`503 rates_unavailable`; pin with a regression test. Also fix the same
pattern in the record path (already caught at `index.ts:312-317` ✓).

**A-2 [major] Insights serve-path KV read failures → raw 500 on three
routes.** `apps/api/src/routes/insights.ts:62` (`getSnapshot()`),
`:101` (`getMarkets()`), `:142` (`getFx()`) are unguarded; the readers
(`apps/api/src/adapters/insights-store.ts:48-53,81-83,97-99`) catch only
*validation* failures, not `kv.get` rejections. Contrast: the live-prices
read on the same route IS guarded and calmly degrades
(`routes/insights.ts:76-81`), and the write side of the same system treats
every failure as non-fatal (`packages/insights/src/markets/run.ts:106-116`).
A transient KV blip blanks the whole Insights section with
`internal_error`. *Fix:* guard all three reads → treat as absent → the
calm 503 "being prepared" answers already exist for that case. Regression
tests with throwing readers (the prices-reader test at
`routes/insights.test.ts:213-225` is the model).

**A-3 [major] `/api/status` (and `/admin` renders) share the same
unguarded-KV-500 class.** `apps/api/src/rates-service.ts:262-281` `status()`
calls `getStatus`/`getSnapshot` without try/catch (the memo-wrapped store
in `index.ts:191-208` doesn't catch `kv.get` rejections either). The rates
*ladder* degrades store failures beautifully (`rates-service.ts:140-167`),
but the status surface does not. *Fix:* per-source try/catch in `status()`
→ omit the broken source's row (or mark `cache.present: false`); keeps
`/api/status` and `/admin` alive during partial KV trouble.

**A-4 [major] fx Yahoo fallback window has zero margin around the y1
anchor — the designed fallback can fail wholesale.**
`packages/insights/src/fx/providers.ts:228` hardcodes `range=1y`;
`fx/compute.ts:203-208` **throws** when no point exists on/before
`last.date − 12 months`; per-pair catch (`fx/job.ts:287-294`) then holds
every pair. Exactly when Frankfurter is down (the fallback's whole
purpose), an unlucky calendar alignment (first bar landing after the
12-months-back target, e.g. a post-weekend bar) can hold all 10 pairs for
the day. Primary path has 400 days (`fx/definitions.ts:37`) — ~35 days of
margin; the fallback has ~0. *Fix:* `range=2y` in `fetchYahooQuotes`
(same 8 subrequests) + a regression test with a weekend-shifted fixture.

**A-5 [minor] Fallback quote-set validation is all-or-nothing.**
`fx/job.ts:116-124` rejects the entire Yahoo set if any one of the 6
currencies is absent/short, discarding the currencies that did answer
during a Frankfurter outage (`fx/providers.ts:254-261` is already
per-currency tolerant). *Fix:* validate per-currency, compute the pairs
whose legs exist (compute layer already degrades per-pair). Behavior
change is additive-availability; needs a spec-check D-entry if adopted.

**A-6 [minor] Worst-case subrequest count sits exactly at the free-plan
cap (50) if KV ops count.** Provider calls worst case 16 EODHD + 16 Yahoo +
1 Frankfurter + 8 Yahoo = 41 (asserted `apps/markets/src/index.test.ts:316-358`);
same-invocation KV ops ≈ 9 (markets get+get+put, fx get+3 cross-reads+get+put)
→ exactly 50. The code claims "≤48" (`apps/markets/src/index.ts:13-15`).
Even if over, the run aborts non-fatally and the 01:30 retry lands it —
honest but the day's write can be lost. *Fix:* pass the already-read
`prev` snapshot into `put…IfChanged` (removes 2 reads) and/or verify
current CF subrequest accounting; extend the budget test to count KV ops.

**A-7 [minor] Cron kind selected by string equality — any unknown trigger
silently becomes `retry`.** `apps/markets/src/index.ts:108`. *Fix:* match
`MAIN_CRON` and `RETRY_CRON` explicitly, log-and-skip anything else.

**A-8 [minor] Stored `stale` flags freeze at write time.**
`markets/compute.ts:333-334`, `fx/job.ts:386-389` — if both crons fail for
days, KV keeps `stale:false` while `asOf` ages. The UI recomputes age
client-side (`WorldMarkets.tsx:167-168`, `WorldCurrencies.tsx:80-84`) so
the display stays honest; machine consumers (CSV export) would not.
*Fix (cheap):* recompute staleness at serve time in
`routes/insights.ts` (one comparison per row), or document the invariant
next to the field.

**A-9 [minor] Boundary inconsistency: Insights Frankfurter parser accepts
non-positive rates; the fx twin drops them.**
`packages/insights/src/parsers.ts:81-83` (throws only on non-finite) vs
`fx/providers.ts:85` (drops `value <= 0`). A zero/negative rate could
enter an `insights:hist:*` series (`schemas.ts:702` values are
`finite()` only) and distort percentiles on the daily-ingestion path.
*Fix:* drop `value <= 0` in `parseFrankfurterTimeseries` + fixture test.

**A-10 [major] `.github/workflows/ci.yml:17` is corrupted: `branches:
ain]` (should be `[main]`) — present since the workflow's creation
(`0bb2610`).** Verified via the GitHub API that CI nevertheless **runs on
push to main** (142 runs, recent all green) — GitHub's filter fails open
on the invalid glob, so the gate has been functioning by accident.
Latent risk: any parser-behavior change silently stops the gate.
*Fix:* `branches: [main]`, one-line, + note in the commit message that
recent history proves it was fail-open, not broken.

**A-11 [minor] `/api/convert` accepts exotic `Number()` forms for
`amount`** (`0x10`→16, `1e2`→100, `" 5 "`→5 — `index.ts:401`): all produce
valid positive finite numbers ≤1e15, so no correctness issue, but the
contract is unpinned. Persian digits correctly reject (NaN). *Fix:* pin
current behavior with contract tests (or tighten to a decimal regex —
behavior change, needs a D-entry).

**A-12 [info] If-None-Match comparisons are exact-string.** All routes
compare the raw header to the exact ETag (`index.ts:322`,
`routes/insights.ts:86,113,154,193`). Browsers echo verbatim; a
`W/`-prefixed or comma-list header (proxy) simply misses → full 200.
Harmless; no action.

**Verified solid (no action):** the four-rung rates ladder and its 2026-10-07
store-failure degradation (`rates-service.ts:140-167,175-231` — read failure
= cache-absent, status/lock failure = skip live rung, persist failure = serve
live anyway); poisoned-entry defense at every KV reader; write-only-if-changed
gates on all insights keys; per-market/per-pair fault isolation; no
unvalidated upstream payload can reach KV (zod at write AND read, final
`build*Snapshot` parses fail-closed); NaN/Infinity cannot leak (`.finite()`
everywhere relevant; non-finite filtered at every provider parser); clock
handling UTC-pure and injectable; both workers' scheduled handlers never
rethrow; `mergeLivePricesIntoSnapshot` never rewinds fresher EOD data and is
excellently tested (`prices.test.ts:365-493`); KV namespace ids identical
across workers; cron slots 3/5 in use (no new triggers needed this session).

## B. API contract consistency

**B-1 [minor] `errorResponse` is duplicated** — `apps/api/src/index.ts:144-159`
vs `apps/api/src/routes/insights.ts:48-56` (documented as avoiding an import
cycle). The insights twin lacks `Retry-After` support and a narrower status
union — drift risk. *Fix (Phase 3):* extract a tiny shared `http-errors.ts`
in `apps/api/src` (no cycle: it imports only types).

**B-2 [minor] Header discipline is good but unpinned for two routes.**
`/api/meta` (`max-age=300`, `index.ts:462-465`) and `/api/status`
(`no-store`, `index.ts:469-472`) have no header assertions anywhere; the
error-path `no-store` is asserted only on insights routes. *Fix:* contract
tests pin all of them (Phase 2 cache-chain suite).

**B-3 [info-good] Input validation exists on EVERY route** (the brief's
specific ask): `?source=` zod (`index.ts:162-166`); convert from/to regex +
amount bounds (`:381-415`); admin form capped + validated (`:546-611`);
internal/refresh header-secret + zod source (`:648-670`); insights
`:id` zod (`routes/insights.ts:173-184`); health/status/meta take no input.
Error envelope (`RatesError`) used uniformly with correct statuses
(400/401/404/413/429/500/501/503 observed in tests). Only gaps: A-11 exotic
forms unpinned; `/internal/refresh` invalid-source 400 untested.

**B-4 [info] `MetaResponse` schema is deliberately duplicated**
(`apps/api/src/meta.ts:22-43` ↔ `apps/web/src/lib/api.ts:102-123`), synced
by api tests. Documented rationale (web bundle must not import the Hono
app). A cleaner home is `packages/core` (pure zod, no platform). Phase 3
candidate, not a defect.

## C. Test-coverage gaps (headliners; full mapping in session notes)

**C-1 [major] `/api/history` + `apps/api/src/history.ts`: zero tests.**
Fingerprint dedup, `HISTORY_MAX_GENERATIONS` cap, `validGeneration`
poison-filtering, KV throwing, ETag/304 + `max-age=60`, invalid source 400.
This endpoint feeds every sparkline (Task 24 honesty fix).

**C-2 [major] `apps/web/src/lib/api.ts`: zero tests** — the trust boundary
for every number the converter displays. Kinds (network/rates/parse),
non-JSON 2xx, envelope with/without `retryAfterSec`, abort/timeout
propagation, `fetchMeta` memo. Includes latent bug: **`fetchMeta` memoizes a
rejected promise forever** (`api.ts:127-144`) — one transient failure at
boot = no meta all session (Converter silently falls back to core statics).

**C-3 [major] `isConfirmedStale` + gold-heal untested**
(`snapshot-store.ts:430-435, 273-314`) — these ARE the honest-stale display
contract (LED/banners) the owner cares about.

**C-4 [major] Both workers' `scheduled` wrappers untested**
(`apps/api/src/index.ts:768-819`, `apps/markets/src/index.ts:102-128`):
cron-kind selection, minute%15 routing, history recording,
one-job-fails-other-survives, prices rung catch. Export a testable seam
(`runScheduled` is already a plain function on the api side; markets needs
the same treatment).

**C-5 [major] `KvMarketsReader`/`KvFxReader`/`KvPricesReader` +
`parseStoredMarkets`/`parseStoredFx` poison paths untested** (only the
prices twin is); `RestMarketsStore`/`RestFxStore` 429/10048 retry ladders
untested (insights + prices twins ARE tested).

**C-6 [minor] `lib/markets.ts` + `lib/fx.ts` clients untested** (the
`insights.ts` twin is). **C-7 [minor] snapshot-store remainder:**
persisted corruption, quota failure, same-generation branch, `force`,
previous-baseline persistence. **C-8 [minor] cron-string test never reads
`wrangler.jsonc`** (`apps/markets/src/index.test.ts:207-210`) — literal
mirror, cannot catch drift. **C-9 [minor] route components have no
component-test environment at all** (no jsdom/testing-library) — banner
logic on `Converter.tsx:185,404`, `LiveRates.tsx:418` untested; a jsdom
setup is a Phase-2+ decision (bundle/dev-dep cost vs value).

**Verified strong:** rates ladder (30 tests incl. incident replay),
insights routes ETag/304/headers, scraper failure/timeout/retry suite,
markets job budgets, prices merge suite, `store.ts` REST retry ladder.
