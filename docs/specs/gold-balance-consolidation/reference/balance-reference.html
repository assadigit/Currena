Mechanics (what the implementation must reproduce)

The "for" pan is the inline-start pan: left in LTR, right in RTL. phys = rtl ? theta : -theta; positive phys = right end down.
RuleValue
One animated valuetheta (degrees, positive = the "for" pan is heavier). Beam rotation, joints, pan translation, hangers and needle all derive from it in the same frame.
Beam angle (unchanged formula)|for - against| / (for + against) x 10, clamped to [3, 10], level when net = 0 or fewer than 3 lanes are readable, level when all unread. Heavier pan goes down.
Physical angle
PansNever rotated or scaled. Only translateY(dy), dy = (L/2) * sin(phys) (opposite sign on the other end), so they hang plumb.
HangersTwo lines per end, redrawn each frame from the joint (beam end after rotation) to the pan top corners at 42% of the pan width either side of its centre.
NeedlePivots at the hub, angle clamp(phys x 3, -32, 32) over a dial of 11 ticks spanning +/-35 degrees (a 3x magnified readout so a 3 degree lean is legible). Hidden when nothing could be read.
Geometrypw = pan width (s: 46% of stage; m/l: min(280, 38%)). L = stageWidth - pw (pan centres sit on the beam ends, pan edges touch the stage edges). swing = (L/2) sin 10 deg. hanger = swing + 22. panH: s 236, m/l 268 (the "stack" scenario proves four weights fit). H = pivotY + hanger + panH + swing + 40. Height never depends on the data.
Motion650 ms, ease-out quartic, only on load and data change. prefers-reduced-motion: jump to the final angle.
BreakpointsBy the card's own width (ResizeObserver / container query), not the viewport: s < 560, m 560 to 759, l >= 760.
Weight rimOne arc segment per driver of the lane, sorted supports, pressures, steady, unread. Green / red / grey / dotted grey. Decorative; counts live in the aria-label and the ledger.
Lane voteSpec 02: at least 2 drivers firing, strict majority; a tie is neutral with the "Split" badge; no readable driver = unread.
