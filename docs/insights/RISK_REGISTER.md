## How this file works

- The **agent** fills in: `level`, `terms_lines` (quoted from the provider's own terms), `terms_read_on`, `attribution`, `method`, `notes`. It never changes `owner_accepts` for a new source.
- The **owner** changes `owner_accepts` (yes or no) and `override` (see below).
- Levels are defined in `RULES.md` section 2 (L0, L1, L2, L3).
- A source with level L3 is never used, even if `owner_accepts` is yes. Only an explicit `override: yes` written by the owner changes that. An override never allows circumvention of a block (`RULES.md` 4.3).
- A source with level L2 is used only while `owner_accepts` is yes.
- Setting `enabled` to no (in the registry or here) removes the source's cards on the next refresh.

## Machine twin

`packages/insights/src/sources.ts` (`SOURCE_RISK_REGISTER`) is the machine
registry this table mirrors: level, owner_accepts (mirrored, never edited for
a new source), `enabled` (the M-6 kill switch), method, runtime, terms lines,
date read, attribution. The generator flows it into
`data/indicators.json` (`sourceRisk` block) and `data/indicator-audit.json`
(level / ownerAccepts / enabled), and the T-15/T-26/T-30/T-31 gates enforce
it. Refresh times note: the operative schedule is 04:20 UTC (ingest), 04:50 UTC
(self-check), 23:30/01:30 UTC (markets), :13 hourly (live prices) — recorded
as an agent choice in CURRENT_STATE_REPORT §S-05 (RULES §4.4.2's "09:13 and
22:13" were the 15-Oct snapshot stamps).
